# Language and Markdown Rules

Read this file when writing documentation, source comments, or user-facing responses.

- Write user-facing responses in Korean.
- Write generated documentation and source comments in Korean by default.
- Add a brief Korean comment describing the role or purpose of each function and constant.
- If Korean causes code corruption, encoding, parsing, lint, type-check, bundling, build, or runtime issues, use English or tool-compatible notation instead.
- Write project Markdown in Korean unless it quotes an external source or requires non-Korean notation.
- Keep headings, lists, code blocks, and tables readable with short sections and clear hierarchy.
- Leave a space after the closing `**` of an emphasis span in Korean Markdown.
- If preview, export, rendering, or encoding issues occur, switch to a tool-safe representation.
